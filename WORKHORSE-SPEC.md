# Workhorse spec: 216 The private-data check is TypeScript run by Bun, and flags little of the project's own code

Revision 2, written to the ticket as rewritten on 2026-10-03: only personal data and secrets are refused, found by patterns with no model. It keeps the machinery, wrapper, protocol and process decisions of revision 1 and replaces its rule table.

## Summary

Port the five private-data gate scripts from shell with embedded Python to TypeScript run by Bun in #109's style, keeping the first version's machinery — the range scan, the markers, the detections log, the rewrite, the scrub into `raw/`, the `.postmaster/` check, the machine protocols and the exit codes — with a new rule table: secrets by shape plus #208's personal-data patterns, no model and no network. The first version's private-context rules are not ported.

## Technical context

- **Language and version**: TypeScript, run by Bun (the repo's Bun 1.4.2 or newer). Node standard modules only.
- **Dependencies used or added**: none.
- **Testing**: `bun run check` (tsc strict, Oxlint, Biome format check, the Bun tests beside every script, runbook references, wiki lint); per-script `bun:test` suites beside each script; `scripts/scrub-heldout.test.ts` (found at least 33 of 33 and 25 of 37, look-alikes at most 3 of 27 and 4 of 23); ported machinery probes named `oracle: <probe>`; per-rule fixtures, at least three positive and three negative per rule, with rule-off proofs; the history census; `scripts/coachman-contract.sh --self-test`; direct CLI transcripts for each acceptance criterion.
- **Constraints**: the user's word — no new Python scripts; private context allowed, only personal data and secrets refused; patterns alone, no model; #109's port style unchanged (one-line `exec bun` wrapper, contract-first `//` header, tests beside each script); machine protocols and exit codes identical to the first version; streaming bounds kept; fixtures fragment-built and every ported file scanner-clean; branch 135 read only through `git show` as the machinery reference, never checked out, nothing run in its worktree, `wb/135-*` never read; branch `scanner-library` read only through `git show` as the pattern reference, never checked out.

## Decisions

- D1, rule table: the check adopts #208's full pattern set with #208's rule names — person: sign-off, author-field, copyright, git-identity, title, self-introduction, relative, credit, name-and-address; email: email; phone: phone; postal-address: street, postcode, po-box, address-field; other-personal: card, iban, ssn, id-number, date-of-birth, health, income, family, residence, employer — plus token and dotenv for secrets and marker for the pseudo-finding: 28 rules. A finding carries its kind and its rule; a relative match yields two findings, person and other-personal, as #208 does. A test asserts the vocabulary equals exactly this set, so a dropped rule cannot creep back and an old name cannot linger.
- D2, secrets: the token and dotenv rules are ported from the first version — key blocks whole as well as headers in every format it covers, prefixed tokens, cloud key ids, long bearer values, secret-ending fields with long values, and `.env` assignments of key-like names with its quoting rules. Transcript keys and contact shapes are not ported: the key rule goes with the dropped set, and contact-identifier assignments stay clean.
- D3, email: #208's mailbox rule — shape, no-reply list, reserved-domain list and role-mailbox list. A sign-off or co-author line flags only when it names a person, under the person rules; vendor, bot and no-reply attribution never flags, since attribution lines are allowed.
- D4, underscore field names count as their words for every word-based rule, not only the phone-number form #208 already joins: the lane normalizes separators or extends the word patterns, whichever it can prove, and fixtures prove each word rule both joined and spaced. Joined camel case is optional.
- D5, git identities are a text shape only: identity assignments in scanned text flag under the git-identity rule. The commit author and committer headers are not a new scan surface; the ticket's scan list is exhaustive.
- D6, narrowings beyond #208 are allowed only when the held-out counts stay at least version 2's and the look-alikes stay at most version 2's; each narrowing is listed with its reason. Widenings are not allowed.
- D7, held-out benchmark: the fixtures are #208's files verbatim (their three-character pieces hold no whole value, and the branch's own scan proves it); the test joins the pieces at run time, scores each set the way #208's runner does — found with any finding, right kind reported, raised on a none line — with token and dotenv as extra kinds that are never the right kind for a personal label, and fails unless the found counts reach 33 and 25 and the raised counts stay within 3 and 4. The card lists both counts.
- D8, machinery probes: every oracle probe that tests machinery or a kept rule is ported, adapted to the new vocabulary, keeping its name after `oracle: ` — the exits, coverage, message, merge, marker, pull-request, logging, log-detection, spans, disable, self-test, rewrite, promote, tree, poll and gate sections; the streaming and decode probes; the round-3 and round-5 repair probes except the path-rule and wiki-page ones. Probes that test dropped rules, key trailers, generated-with footers, UNC and file-URL paths, scratch tails, and wiki page-content are dropped, each listed with its reason.
- D9, JSON nesting: the decode limit stays 64 levels as ported machinery, stated in the header and tested — a value at depth four flags, a value at depth 64 flags, deeper text still scans plain.
- D10, carryover: the eleven files take the first version's diffs; the wiki-lint check entry and the SKILL.md lint-list hunk are omitted with reasons for the card; a carried test whose fixture trips only a dropped rule gets a kept-rule fixture swap, noted for the card. For each file the diff against main equals the first version's diff, or the card says why it differs.
- D11, exit codes and protocols are byte-identical: `--spans`, `--safe-path` and `--log-detection` never exit 1; the rewrite script never exits 1; all six stdout protocols keep their shapes; the detections-log entry shape, `via: marker` suppression records, and marker-faults-never-logged hold. `--log-detection` and the disable hook take the new 28-name vocabulary plus messages, merges and markers; unknown names, old rule names included, behave as the reference behaves for unknown names.
- D12, reasoning-block removal is promote-only, not a scan rule: the three shapes leave whole, the copy stays valid where the source parsed, and each removal is reported as the `reasoning-block` pseudo-rule in the promote output and the detections log. It is never valid in a marker.
- D13, streaming bounds are kept: memory bounded by the longest line, the 8 MB committed-blob cap for key-block lookup, `--files` and `--spans` in streaming passes. Proven as the first version proves it: a multi-megabyte scan under `ulimit -v`.
- D14, `--history` stays removed; the census is the range scan from the root plus `--files` over the root tree, at BASE by default, at current main as well when main has moved. Target: at most 50 suspects, each verdicts as made-up test data or not on the card.
- D15, the open P3s against dropped rules are void; the P3s against kept machinery and secrets are carried as known behavior and the port keeps each quirk; rule-off proofs, the bug-34 class, are now required by the thirteenth criterion instead of deferred.
- D16, fixtures build every made-up value from fragments at test time; each ported file carries a source-is-clean control; the branch passes its own scan, so no committed file holds a value the check would find.
- D17, no rule excuses a match by file path or directory: a secret in a test file is still a secret, and path-based excuses would open a hole the review lenses would file.
- D18, the check makes no model call and no network call; reviewers verify that by reading.
