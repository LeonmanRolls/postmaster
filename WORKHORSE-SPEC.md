# Workhorse spec: #179, A workhorse shows every acceptance criterion working, and keeps at it until it can

_Shared spec written by the coachman from the two lane specs, per the user's word in planning round 1. Identical in both lanes' worktrees. Both lanes implement from this same file, in blinkers as before._

## Summary

The workhorse brief becomes a build–exercise–fix loop driven by per-criterion checks the spec specifies: each lane runs every criterion's check the way the criterion will really be used, keeps the evidence under its worktree's `.postmaster/verify/`, and a new TypeScript script holds `WORKHORSE-SUMMARY.md` to that shape so the coachman reads the evidence when it judges the lanes.

## Technical context

- **Language and version**: TypeScript run by Bun for the new evidence script (the repo's existing script style: `scripts/run-clash.ts`, `scripts/synthesis-shares.ts`); markdown only where the runbooks and template already are.
- **Dependencies used or added**: none. `node:fs`, `node:path` and `bun:test` only.
- **Testing**: `bun test scripts/summary-evidence.test.ts` for the four summary shapes in AC8; each check under `## Showing each criterion`, run as it says; the waybill's gate for the rest. A fixture run scoring clean is the landing condition for this coachman-contract change, not a test this branch runs; the AC2 row says what the postmaster reads in it. AC3's browser path has no web fixture.
- **Constraints**: the blind acceptance tests stay hidden from the lanes; a lane shows its criteria by its own means. Evidence lives only under `.postmaster/verify/`, which `verify.sh arm` tells git to ignore in every project it arms; the brief relies on that, not on this repo's own `.gitignore`. Browser work goes through the target project's own browser library from a shell command in the lane's worktree, never a shared browser server. No web fixture is invented here. No harness-specific wording enters the flow: the brief's no-backend clause is generic, and the coachman fills it from the waybill and `harnesses.md`.

## Decisions

1. **Script name and interface.** `bun scripts/summary-evidence.ts <summary.md> <worktree> [--ticket <file>]`. The coachman runs it as it runs `synthesis-shares.ts`, `bun --no-env-file --config=/dev/null <tool>/scripts/summary-evidence.ts …`, so no `.env` or `bunfig.toml` from a worktree is read. The criteria are read the way `ticket-check.sh` reads them: the list under `## Acceptance criteria` numbered 1, 2, 3, where indented lines, nested lists and lines running straight on belong to the criterion above, so the two scripts never count a ticket differently. They are matched by number, so wording drift does not matter. A cited path counts as under `.postmaster/verify/` only once `..` and symlinks are resolved, so no entry can point the coachman outside it. The ticket defaults to the armed copy at `<worktree>/.postmaster/verify/ticket.md`, and `--ticket` accepts that shape or a waybill read from `## Ticket` to `## Project profile` (the `verify-examples.sh` precedent). Exit 0 holds; 1 usage or unreadable input; 2 a criterion is missing from the evidence section, cites evidence that does not exist or lies outside `.postmaster/verify/`, or is claimed shown with no evidence. `not shown: <reason>` is valid and does not fail the shape. The expected criteria come from the ticket, never inferred from the summary.
2. **Evidence section shape.** `WORKHORSE-SUMMARY.md` gains `## Evidence`, one entry per acceptance criterion numbered as the ticket numbers them: one or more worktree-relative paths under `.postmaster/verify/`, or the line `not shown: <reason>`. The rest of the summary stays as today.
3. **Standalone script; no `verify.sh` change.** One lane spec wired the validator into `verify.sh summary`; this spec keeps it a separate script the coachman runs at harvest beside `verify.sh summary`. The ticket asks for "a script", the harvest step runs every run either way, and `verify.sh`'s contract and self-tests stay untouched.
4. **The spec's checks bind the lanes.** Each criterion's check is run as specified; a lane may add checks of its own, never drop or weaken one the spec specifies. Where the ticket has no `User journey`, the spec's steps for a surface-touching criterion are the journey the lane walks and reports.
5. **No browser backend.** The brief tells the workhorse when its harness has none — the coachman knows the harness from the waybill and the backends from `harnesses.md`, so the clause names no harness. The summary marks those criteria `not shown: <reason>`; the coachman's render gate covers the surface, as today.
6. **"Counts against that lane."** The script's exit 2 output is the count: the coachman names each problem on the checkpoint 1 card and treats a criterion claimed as shown without evidence the way it already treats a check claim its run contradicts. No new scoring system.
7. **The loop's last step is unchanged.** The brief still requires `<tool>/scripts/verify.sh run .` just before the summary. The loop's own passes are what the workhorse uses to finish; that final run is what the summary's `## Checks` quotes. The evidence the summary cites comes from the loop's last pass, on the final code: a transcript or walk taken before a later code change is taken again. How a lane shows which code its evidence ran on is its own choice.
8. **Template section heading, place and shape.** `## Showing each criterion`, before `## Tasks`, so a task can name how it will be shown without a second planning document. It is a table, one row per criterion: the criterion in full, word for word from the ticket, then its check and the expected output. The reviewer judges each check against the criterion beside it, and a lane whose copy of the ticket is older than the spec still reads the current wording.
9. **TypeScript, and what to copy from #109's port.** By the user's standing rule, every script this ticket writes or changes is TypeScript run by Bun. Where a ticket changes an existing script, or needs something #109 has already ported, it copies the port's files unchanged from commit `b8e5e6485f77` (`git show b8e5e6485f77:<path>`) in a commit of its own, then makes its change in the TypeScript, so #109's later merge meets the same files. For this ticket that is nothing:
   - It changes no existing script. `scripts/verify.sh`, `scripts/verify-journey.sh` and the fixture scripts stay as they are.
   - Its one new script is TypeScript already. It reads the ticket and its criteria itself, as `scripts/synthesis-shares.ts` reads its inputs, and imports nothing from `scripts/lib/`. The port's ticket readers sit unexported inside `verify.ts`, `verify-journey.ts` and `ticket-check.ts`, so none can be used without changing it.
   - A lane whose script does import a `scripts/lib/` module copies that module, and every module it imports, unchanged, in a commit of its own before the script's, and names the copy in its summary. It copies no config file: the script needs none without a `.sh` wrapper, and the port's `package.json` would drop the `lint` script the gate runs.
10. **A stuck workhorse.** A check the spec gives that cannot pass as written, or that contradicts the ticket, is not the lane's to change, since changing an approved check is the user's call. The workhorse writes `WORKHORSE-BLOCKED.md` naming the check, what it shows and the change it proposes, and the coachman resumes it with the ruling. Anything else it cannot get working does not block: it finishes, with the failing transcript as that criterion's evidence, what blocks it under what it did not do, and that criterion's verdict as not met. The brief sets no limit of its own on the loop; the coachman's 90-minute stall cutoff bounds it, as today.
11. **What the landing fixture run shows.** `fixture.sh score` reads no summary and no evidence, so a clean score does not show the loop working. The AC2 row names what the postmaster reads in that run's records when it scores it. A score line for the evidence is left to a ticket of its own: under Decision 9 it would mean copying #109's port of `fixture.sh`, which predates the lane scoring that #159 (A fixture run scores each lane's own branch against the hidden tests) added on main.
