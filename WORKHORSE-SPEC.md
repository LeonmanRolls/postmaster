# Workhorse spec: 202 After the workhorses and after each review round, check for a lane's reach outside its own worktree

## Problem / feature

Nothing in the flow notices when a lane touches files outside its own folder. On 2026-09-27 a workhorse wrote a file into a project's main checkout. On 2026-10-03, in [#200, Run every lane in its own process space, so it cannot kill processes it did not start](https://github.com/brindlewick/postmaster/issues/200), a reviewer merged its own fix into the code it was reviewing. Both were found only by hand. Done: every run checks for this at set points and acts on what it finds.

## Acceptance criteria

1. The reach check runs after the workhorses finish, for the workhorses; after each review round, for that round's reviewers; and before the ship card, for the main checkout.
2. Every check records its result in the run's log, a clean result included.
3. Every check lists each changed or new file in the main checkout.
4. Every check says when the main checkout is not on its default branch; the default branch moving forward, as when the postmaster pulls, is not a change.
5. After the workhorses and after each round, the check lists every place outside a lane's folder that the lane read or wrote, from the lane's own record.
6. Around each review round, the check compares this run's own branches and synthesis worktree before and after the round, and names what changed.
7. A write outside a lane's folder is a finding about that lane; a read, or an attempt that was refused, is a note.
8. A workhorse's finding, or a main checkout change no lane's record explains, goes to the user before synthesis, with the coachman's advice on using that lane's work.
9. Whenever a reach goes to the user, the run waits for their answer.
10. A reviewer's finding voids that reviewer's verdict for the round.
11. After each round, before any fix, the run's own branches and synthesis worktree are put back as they were before the round, so fixes build on reviewed code.
12. A reviewer's write outside this run's own branches and folders (its synthesis, workhorse and reviewer folders) also goes to the user.
13. Everything else the check finds is shown on the ship card and stops nothing, including a main checkout change found after a round or before the card.
14. The ship card's reach section is built from the run's log and lists every finding, note and voided verdict, and any check that was skipped.
15. Each kind of thing the check looks for has one test that must find it and one that must find nothing.
16. A fixture run scores clean with the check in place.
17. The fixture score fails a run whose check found a reach, skipped a point, or could not read a lane's record on a tool it supports.

## Decisions

- **D1 (proposed)** During a round, the check compares only this run's own branches and synthesis worktree. Why: other runs commit, and the postmaster pulls, while a round runs, and a lane that moves another branch shows it in its own record. Instead of: comparing every branch, which would report other runs' work as noise.
- **D2 (proposed)** A change is tied to a lane when the lane's record shows it writing that file or moving that branch. Why: a branch can be moved from any folder, so the folder alone may not name the lane. Instead of: tying only writes inside a folder, which would void a whole round when one lane could be named.
- **D3 (proposed)** A voided verdict follows the rule for a reviewer that died mid-round: it never counts as clean, its findings are still checked, and the reviewer reviews again if another round runs. Why: the flow already handles a reviewer that did not really review this way. Instead of: dropping the voided reviewer's findings, which would lose real defects.
- **D4 (proposed)** A change to the run's branches or synthesis worktree that no record explains voids every verdict of the round, and another round runs, counting toward the limit of three. Why: a round whose code moved under it reviewed nothing, and the flow can put the code back itself. Instead of: stopping to ask the user.
- **D5 (proposed)** Putting back keeps a copy of what it undid, and moves any new file out of the synthesis worktree into the run's records. Why: the next round's checks refuse a worktree holding stray files, and deleting them could lose work. Instead of: leaving them in place, which would stop the next round.
- **D6 (proposed)** The first test is the real command from #200: three git commands in one line, a look, the merge, then another look. Why: a check that judged only the first part of a command would pass it. Instead of: a made-up single command.
- **D7 (proposed)** Reading system files, the run's copy of postmaster and the lane's own instructions and settings, and using the temp folder, caches and the lane's tool's own data folder, are normal and not reported. Why: every codex command names the system shell, so reporting it all would bury the real reaches. Instead of: reporting every path outside the folder.
- **D8 (proposed)** Anywhere else outside the lane's folder, a write is a finding, including the home folder and other projects. Why: a write there is as much a reach as one into the main checkout. Instead of: counting only the main checkout and the run's worktrees.
- **D9 (proposed)** Running git on another folder counts as a write unless it only shows something. Why: the 2026-10-03 reach was a git merge, not a file edit. Instead of: counting only file edits as writes.
- **D10 (proposed)** A write counts as done even when its command failed; only a refusal, by the tool or by the system, makes it a refused attempt. Why: a merge that landed must not be reported as a note. Instead of: treating every failed command as refused.
- **D11 (proposed)** The postmaster passes every reach on to the user rather than deciding it. Why: a lane reaching outside its folder is the user's to judge. Instead of: letting the postmaster rule, as it may today on such questions.
- **D12 (proposed)** In a fixture run, where no one is asked, the postmaster rules on a reach itself, and the score fails. Why: a fixture run has no user to wait for. Instead of: stalling the fixture run.
- **D13 (proposed)** A lane whose record cannot be read is reported as not checked, never as clean, and that alone voids nothing. Why: an unreadable record must not pass for a clean one, nor stand for a reach. Instead of: leaving that lane out.
- **D14 (proposed)** A fault in the check itself, such as a main checkout it cannot read, stops the run's leg, as a fault in any other check does. Why: a check that did not run must not look like a pass. Instead of: carrying on without it.
- **D15 (proposed)** The reach check becomes part of the coachman's contract. Why: a later change to it then needs a fixture run before it lands. Instead of: leaving it out, so its answers could change untested.
- **D16 (proposed)** No fixture run plants a reach. Why: a model cannot be made to reach on cue, and the tests cover the same cases. Instead of: staging a reach in a fixture run.
- **D17 (proposed)** A command not known to change files counts as reading the paths it names. Why: guessing at writes would void verdicts for plain reads. Instead of: counting every outside path a command names as a write.
- **D18 (proposed)** The ship card names a path inside the project relative to it, and a path outside the project only as outside; the full path stays in the run's log. Why: the card goes into the public pull request, and a full path can name the home folder or another project. Instead of: full paths on the card.

## Out of scope

- Stopping lanes from reaching outside, and cleaning up after them.
- Writes a command makes without naming the path; the main checkout and branch checks catch what they change.
- Telling a write a sandbox blocked from one that landed.
- Checking the coachman or the postmaster: only lanes are checked.

## Direction

Linux and macOS, in TypeScript run directly by Bun, with no shell wrapper. It changes the coachman's steps, so it lands only after a fixture run from its branch scores clean. It reads each lane's own record of its tool calls, never the lane's report, and contacts no remote. The check before a run starts, the checks on reviewers' own copies, and the cards of earlier runs stay as they are.

### Checks

Every check runs `scripts/reach.ts` on **the run layout**, fresh per lettered case: a temporary repository `R` on its default branch `main`, ignoring `.postmaster/` and `.worktrees/`, its `origin/main` one commit behind `origin`; `D = R/.postmaster/runs/T`, its `run.json` giving lanes `codex`, `claude`, `muse`, `mimo`, `pi` and `grok` that harness, and workhorses `codex` and `mimo`; synthesis worktree `R/.worktrees/T` on `T`; workhorse worktrees `R/.worktrees/T-<lane>` on `wb/T-<lane>`; per round, scratches `R/.worktrees/T-rev-bug-<lane>` detached at `T`, recorded as `review-round.sh` records them; `HOME` temporary. Streams take each harness's exact shape, what they record is done on disk, and each stays inside its folder unless the case says otherwise.

- **C1** On a clean layout, `check D workhorses`, `before D 1` then `check D r1`, and `check D card` → each exits 0. **At the base:** no `reach.ts`, and the runbook has no such step.
- **C2** After C1, `D/actions.jsonl` holds one `reach` line per point reading clean; after C3, each point's line names its finding. **At the base:** `log-action.sh` refuses the action `reach`, exit 1.
- **C3** In `R`, 25 untracked files, one of them `probe/a.txt` in a new folder, and a tracked change; each point → all 26 paths, `probe/a.txt` as itself, exit 2; `origin/main` never moves. **At the base:** `check-target.sh` fetches, lists 20 of the 26 paths with `?? probe/`, exit 2.
- **C4** (a) `R` switched to a new branch `x` → named as off the default branch, exit 2. (b) A commit added to `main`, tree clean → clean, exit 0. **At the base:** `check-target.sh` prints `branch x` and exits 0 for (a), and nothing flags it.
- **C5** Per harness, a stream that writes `R/out.txt` by file tool, reads `R/.worktrees/T-mimo/a.ts` twice and then writes it, runs `cat ~/n.txt`, `git -C R/.worktrees/T log -1`, `cat /tmp/x >/dev/null` and `bun test`, and writes `in.txt`; `reach.ts stream D <lane> <stream> R/.worktrees/T-codex` → besides `expected` lines, exactly: `out.txt` write (main checkout), `a.ts` write once (another worktree), `n.txt` read (elsewhere), `R/.worktrees/T` read (synthesis worktree); exit 2. A Claude Code bug lane's write found only in its copied task file is found the same way. A `grok` lane, an unreadable stream, or one with no recognized tool call: `not checked`, exit 3. **At the base:** nothing reads a stream for paths.
- **C6** `before D 1`, one change, `check D r1`, for (a) none; (b) a commit in a scratch; (c) `git -C R/.worktrees/T merge --ff-only <that commit>`; (d) a commit on `99` in `R/.worktrees/99`; (e) an untracked file in `R/.worktrees/T`; (f) a tag added, `refs/remotes/origin/main` moved, and `main` moved forward → (a), (b), (d), (f) nothing named; (c) `refs/heads/T` and the synthesis head, both hashes each; (e) the file. **At the base:** only the runbook's hand assertion that the synthesis worktree is clean, which (c) passes.
- **C7** From C5: `out.txt` and `a.ts` are findings, `n.txt` and the synthesis read are notes. A Claude Code read its settings deny, and a MiMo `echo x > R/o.txt` answered `Permission denied` → `refused` notes, exit 3. `echo x > R/p.txt; false`, exit 1 with no refusal → a finding. `some-tool R/q.txt`, a command not known to write → a read note. **At the base:** nothing classifies them.
- **C8** (a) `codex`'s stream writes `R/out.txt`; `check D workhorses` → exit 2 and the runbook escalates before `stage.sh <dispatch> synthesis`. (b) No stream names it, but `R` has an untracked file → exit 2, escalated the same way. (c) Only a read → exit 3, no escalation. **At the base:** no reach step before synthesis.
- **C9** (a) After C8 (a), `D/.escalation-ready` is set, `runs-status.sh` gives the run NEXT `RULE`, and no `stage` line for `synthesis` follows until a ruling resumes the leg. (b) After C12, the same, with no `apply` line and no next `review-launch` until the ruling. **At the base:** no reach escalation exists.
- **C10** Reviewers `bug:codex` and `bug:mimo`, `before D 1`, `mimo`'s stream holds the event in the technical notes and its merge is made; `check D r1` → a finding for `mimo` naming the synthesis worktree and `refs/heads/T` with both hashes, a `degrade` line for `mimo` (bug, r1, cause `reach`) and none for `codex`. (b) `mimo`'s stream runs `git update-ref refs/heads/T <sha>` in its scratch → only `mimo` voided. (c) No stream naming the merge → `degrade` lines for both. **At the base:** no reach step in a round.
- **C11** After C10 (a) with an untracked `R/.worktrees/T/u.txt` added, `restore D r1` → `T` and the synthesis head are back at their hashes before the round, the undone change is saved under `D`, `u.txt` is moved under `D/reach/`, and `verify.sh run R/.worktrees/T D` then runs instead of refusing. **At the base:** nothing puts the branch back, and `verify.sh run` refuses a worktree holding `u.txt`.
- **C12** `mimo`'s stream writes `R/x.txt` during a round → `mimo` voided, and the result is marked for the user; a write into `R/.worktrees/T-codex` instead → voided, not marked. **At the base:** no reach step in a round.
- **C13** A `mimo` read of `R/README.md`, an untracked file in the synthesis worktree no stream names, and an untracked file in `R` at `check D r1` and at `check D card` → notes on the card, no `degrade` line, no escalation. **At the base:** nothing reports them.
- **C14** On one layout, C8 (a), C10 (a), a `codex` write to `$HOME/other/x`, `check D card`, then `landing.sh card-block D R/.worktrees/T <checkpoint>` → `## Reach` with the main checkout as it stands, `codex`'s write as `out.txt` and its other write as outside the project with no path, `mimo`'s write into the synthesis worktree and its round-1 bug verdict voided; no line holds `$HOME` or `R`'s absolute path. With the `check D card` line removed → the card point shows `not checked`. For a dispatch with no `reach` line → the block the existing tests expect. **At the base:** `card-block` renders `## Checks`, `## Open findings` and `## Not re-reviewed` only.
- **C15** `bun test scripts/reach.test.ts` → passes, with the cases of C1 to C14 each beside its opposite through the same command, and a codex `/bin/bash -lc` command inside its folder that prints nothing. **At the base:** no such test.
- **C16** At landing, `fixture.sh score` on a fixture run dispatched from the branch → the eight existing checks and `reach` ok, exit 0. **At the base:** none of the score's eight checks reads `reach`.
- **C17** `bun test scripts/fixture.test.ts` on a record with `reach` lines for the workhorses, each round and the card and no finding → `reach` ok; on records missing a point, holding a finding, or holding `not checked` for a `mimo` lane → `FAIL`. **At the base:** none of the score's eight checks reads `reach`.

### Technical notes

- `scripts/reach.ts`, run as `bun --no-env-file --config=/dev/null <tool>/scripts/reach.ts` as `summary-evidence.ts` is ([`coachman.md` L510](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/coachman.md#L510)), with no `.sh` wrapper: `stream D <lane> <events> <own-folder>`, `before D <n>`, `check D workhorses|r<n>|card`, `restore D r<n>`. `stream` and `check` exit 0 clean, 3 notes only, 2 a finding, 1 cannot check. Lanes and harnesses come from `run.json`'s config, workhorses from `manifest.json`, a round's reviewers from `logs/review-r<n>.json`. (C1, C2, C5, C6, D13, D14)
- The main checkout goes through [`check-target.ts`](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/check-target.ts#L26-L33), which fetches at L26 and prints at most 20 `git status --porcelain` lines at L28-L33, folding a new folder into one line. Add a form for this check that lists every path (`-uall`), every new file by its own name, says when the checkout is not on its default branch, treats the default branch moving forward as no change, and does not fetch; the default form stays as it is for its callers. (C3, C4, D14)
- The tools with a reader are codex, Claude Code, Muse Code, MiMo Code and pi; grok and Antigravity have none yet and read `not checked`, as does a record that cannot be parsed or in which no tool call is recognized. Shapes, as [`view-stream.ts`](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/view-stream.ts#L177-L425) parses them: codex `item.completed` items `command_execution` (`command` is `/bin/bash -lc '…'`, with `aggregated_output`, `exit_code`) and `file_change` (`changes[].path`); Claude Code `assistant` `tool_use` blocks (`name`, `input`) and their `tool_result`; MiMo `tool_use` with `part.tool` and `part.state` (`input`, `output`, `metadata.exit`); pi `tool_execution_start` (`toolName`, `args`) and `tool_execution_end`; Muse Code `tool.result` (`correlation_facts`, `edit_facts`, and the result text). pi's shape is not yet checked against a recorded stream ([`harnesses.md` L674-L677](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/harnesses.md#L674-L677)). Claude Code's `/code-review` calls are in its forked task's file ([L533](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/harnesses.md#L533)), which the bug harvest copies to `logs/<prefix>-claude-task-*`: read it with its lane. The whole record is read, after any resume. `harnesses.md` gains a table of these shapes and each harness's settings and data folders, with `reach.ts` as its executable form. (C5, D13)
- One line per lane and path, with the strongest access the lane had there. Places: inside is the lane's worktree or scratch; the main checkout is the repository outside `.worktrees/`; the synthesis worktree is `.worktrees/<T>`; any other path under `.worktrees/` is another worktree; the rest is elsewhere. Normal, for reading: paths outside `$HOME` and the repository, the run's tool checkout (`run-meta.sh path`), the lane's prompt and brief files in the dispatch folder, and `~/.codex`, `~/.claude`, `~/.claude.json`, `~/.config/muse`, `~/.config/mimocode`, `~/.mimocode`, `~/.pi/agent`; for reading and writing: the temp folder (`$TMPDIR`, `/tmp`, `/private/tmp`, `/var/folders`), `/dev`, `~/.npm`, `~/.cache`, `~/.bun`, and the lane's own `XDG_DATA_HOME`. (C5, C7, D7, D8)
- Shell commands: split on `;`, `&&`, `||`, `|` and `$(…)`, unwrap `bash -lc`, apply `cd`, and resolve `~`, `$HOME`, relative paths, `..` and links from the lane's folder; skip a path that needs another variable or a glob. `git -C <path>`, `--git-dir`, `--work-tree`, `GIT_DIR=` and a preceding `cd` aim git at a folder. Git reads with `status`, `diff`, `log`, `show`, `rev-parse`, `rev-list`, `merge-base`, `ls-files`, `ls-tree`, `cat-file`, `show-ref`, `for-each-ref`, `describe`, `blame`, `grep`, `config --get`, `worktree list`, `stash list` and a bare `branch` or `tag`; every other subcommand writes. Every git call in a command is judged, and the strongest wins. Redirects and the targets of `cp`, `mv`, `rm`, `mkdir`, `touch`, `tee`, `sed -i`, `ln`, `install` are written; any other path a command names is read. `refused` needs `Permission denied`, `Operation not permitted`, `Read-only file system` or the harness's own refusal in the result, or a read of a missing path, never the exit status alone. (C5, C7, D6, D9, D10, D17)
- Refs: `before` records this run's refs, `refs/heads/<T>` and `refs/heads/wb/<T>-*` (no other branch, tag or remote ref), the main checkout's head and branch, and the synthesis worktree's head and `status --porcelain -uall`; `check r<n>` compares them before the round's teardown and prints each change with both full hashes. A moved run ref is a lane's when its stream holds a git write in the worktree that has the ref checked out, or a git write naming the ref. A lane's git write that moves any other branch is a finding from its own stream. (C6, C7, D1, D2)
- The void is a `degrade` line (the lane, `<lens> r<n>: reach`) for that lens only, written by `check r<n>` as [`review-round.ts` L380-L381](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/review-round.ts#L380-L381) writes a timeout, under the [DEGRADED rule](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/coachman.md#L1323-L1340): a round run again counts toward the cap of three, and a style lane stays DEGRADED, since style runs in round 1 only. An unexplained change to `T`, `wb/T-*` or the synthesis worktree's tracked files degrades every reviewer of the round. `not checked` writes no `degrade` line. (C10, D3, D4, D13)
- `restore` saves `git diff --binary <before>` for each moved run branch, and for the synthesis worktree's tracked changes, under `D/reach/`, then resets each worktree that has a run branch checked out to its commit before the round, and moves every new file `git status --porcelain -uall` shows in the synthesis worktree to `D/reach/r<n>/`, keeping its path. [`verify.ts`](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/verify.ts#L776-L783) refuses a worktree holding any such file, so the next round's checks would not run otherwise. (C11, D5)
- A finding at `workhorses`, an unexplained main checkout change there whoever made it, and a reviewer's write outside `T`, `wb/T-*`, the synthesis worktree, the workhorse worktrees and the round's scratches are escalated like any escalation, after `restore` in a round. [`postmaster.md` Stage E](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/postmaster.md#L436-L450) step 3 gains a reach, which today step 2 lets the postmaster rule on; in a fixture run it rules itself, as for the spec ([L359-L362](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/postmaster.md#L359-L362)). (C8, C9, C12, D11, D12)
- Card only: a read, a refused attempt, a new untracked file in the synthesis worktree that no stream names, and a main checkout change at a round or at the card. (C13)
- Records: [`log-action.ts`](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/log-action.ts#L45-L46) gains the action `reach`, one line per point and one per finding or note, with full paths. [`landing.ts` `card-block`](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/landing.ts#L36-L48) appends `## Reach`: the main checkout as it stands before the card, every finding, note and void from the earlier points, a missing point as `not checked`, and nothing for a run whose pinned tool has no `scripts/reach.ts`, so Stage F still matches earlier cards. On the card, a path in the repository is relative to it and a path outside it reads `outside the project`, since the card goes into the pull request ([`postmaster.md` L596](https://github.com/brindlewick/postmaster/blob/ede70e2/skills/postmaster/postmaster.md#L596)). The [fixture score](https://github.com/brindlewick/postmaster/blob/ede70e2/scripts/fixture.ts#L429-L438) gains a `reach` check: lines for the workhorses, each round logged and the card, no finding, and no `not checked` for a lane whose tool has a reader; it does not apply to a run whose pinned tool has no `scripts/reach.ts`. (C2, C14, C16, C17, D12, D18)
