# Workhorse spec: 216 The private-data check is TypeScript run by Bun, and flags little of the project's own code

## Summary

Port the five private-data gate scripts from shell with embedded Python to TypeScript run by Bun in #109's style, keeping every CLI protocol and exit code, and narrow the detection rules so the main-history census drops from 928 suspects to at most 50 with none of the ticket's listed false-positive kinds. The run ports faithfully first with a differential test pinning behavior, then removes false positives on purpose with each difference listed and reasoned.

## Technical context

- **Language and version**: TypeScript, run by Bun (the repo's Bun 1.4.2 or newer). Node standard modules only.
- **Dependencies used or added**: none.
- **Testing**: `bun run check` (tsc strict, Oxlint, Biome format check, the Bun tests beside every script, runbook references, wiki lint); per-script `bun:test` suites beside each script; `scripts/scrub-diff.test.ts` (differential test); ported oracle tests named `oracle: <probe>` (at least 187); `scripts/coachman-contract.sh --self-test`; direct CLI transcripts for each acceptance criterion.
- **Constraints**: the user's word — no new Python scripts; #109's port style unchanged (one-line `exec bun` wrapper, contract-first `//` header, tests beside each script); machine protocols and exit codes byte-identical to the first version; streaming bounds kept; fixtures fragment-built and every ported file scanner-clean; branch 135 read only through `git show`, never checked out, nothing run in its worktree, `wb/135-*` never read.

## Direction check

- No new Python scripts, redo them in TypeScript (user's word): the five scripts become five `.ts` files with thin wrappers; the no-Python check is scoped to those ten files (other files under `scripts/` on main already mention Python in fixtures and comments, so a repo-wide search cannot be the check).
- Port faithfully, then remove the false positives, listing each: the differential test pins the faithful port, and every reference-vs-port difference ships with its reason.

- Ordinary run, review turnpikes on the TypeScript: this spec is the run's one spec; review runs on the port.

- Fixture run before landing (coachman-contract change): the postmaster dispatches it from the final head; this run keeps the contract files' behavior identical so the fixture run judges the finished port.
- AGENTS.md, TypeScript with a functional core and side effects at the edges: the scan engine is pure over lines and units; git, filesystem and log writes sit at the CLI edges.
- AGENTS.md, tests written alongside the change, lint and typecheck clean: every ported script ships its tests in the same branch; `bun run check` is clean before the summary.

- AGENTS.md, nothing repo-specific or harness-specific: no hardcoded hosts, paths, lane or harness names in the port; the census head is a parameter defaulting to BASE.

No departures; no complexity tracking.

## Decisions

- D1, differential design: the corpus holds at least 200 lines from all three sources the ticket names (oracle cases, self-test controls, history lines), each line labelled with its source. Kept true positives are fragment-built at test time; reference-only flags and clean-under-both lines are committed verbatim. The reference suspect lists are committed as recorded fixtures; a documented regeneration command re-extracts `git show 135:scripts/scrub-check.sh` to a temp dir and re-runs the reference side over the corpus. Regeneration needs Python 3; the gate never runs it and never needs Python. The test fails when the TypeScript side differs from its recorded lists, and fails when any reference-vs-port difference lacks its reason.
- D2, `--self-test` is kept in every ported script and runs the same control suite its `.test.ts` drives, as `host.sh --live-test` and `coachman-contract.sh --self-test` do on main. It is a developer convenience, not a machine protocol, so keeping it changes no contract.
- D3, no-Python scope: the check is a case-insensitive search for `python` over exactly the five wrappers and five implementation files. Test files and docs may name Python only where they must (the differential regeneration note); nothing shipped invokes it.
- D4, oracle port mapping: every one of the 187 probes becomes a `bun:test` test named `oracle: <original-probe-name>`, colocated with the script it probes. `grep -rho 'oracle: [^"]*' scripts/*.test.ts | sort -u | wc -l` counts at least 187, and `bun test scripts/ -t 'oracle: '` passes. The oracle's self-test probes become probes that the ported `--self-test` flags and their `.test.ts` drivers pass.
- D5, host-rule narrowing: `process.env.HOME`, `this.home`, `Path.home` and their kin stop flagging; private IPs, CGNAT, private-suffixed hostnames such as `metrics` on `.internal`, and tailnet names keep flagging per the oracle's host probes. Starting diagnosis: the rule reads a private-looking suffix after an identifier chain as a hostname. The lane chooses the mechanism; the census and the oracle judge it.
- D6, account-id and key-rule narrowing: thread, workspace and session ids and `session`/`email` field names in test code and recorded streams stop flagging; the oracle's id and field probes (`org-…` ids, UUIDs beside account context, `userEmail`/`sessionContext` with present values) keep flagging. The scanner's core threat is harness transcripts, so the narrowing is by shape and surrounding text, never by excusing streams.
- D7, path-rule narrowing: a `/home/<segment>` match whose segment is a file name (such as `<trial>/home/note.txt`) stops flagging; `/home/<user>/…`, `/Users/<user>`, `/root/<name>`, `~<user>/`, harness scratch paths and the UNC and `file|ssh` URL branches keep flagging per the oracle's path probes.
- D8, secret-constant narrowing: the made-up secret constants in the settings tests and the `user.email=t@t`-style git settings stop flagging; the oracle's token, dotenv and field probes keep flagging. No rule may excuse a match by file path or directory: a secret in a test file is still a secret, and path-based excuses would open a hole the review lenses would file.
- D9, census: the head defaults to BASE `0620bfc` so the count compares with the 928 baseline; the head is a parameter, and if main has moved by ship time the run scans both BASE and current main and reports both. Method, as the first version's: range scan from the root commit plus `--files` over the root tree. Target: at most 50 suspects, none of the ticket's listed kinds.
- D10, criterion-5 method: for each of the thirteen files, apply branch 135's diff onto main as it is now and confirm `git diff main...HEAD -- <file>` equals `git diff $(git merge-base origin/main 135)...135 -- <file>`. Main is at the merge base, so the diffs apply directly; any deviation is explained on the card.
- D11, exit-code matrix and protocols are byte-identical: `--spans`, `--safe-path` and `--log-detection` never exit 1; the rewrite script never exits 1; all six stdout protocols keep their shapes; the detections-log entry shape, `via: marker` suppression records, and marker-faults-never-logged hold; `--log-detection` still refuses `marker`.
- D12, streaming bounds are kept: memory bounded by the longest line, the 8 MB committed-blob cap for key-block lookup, JSON nesting to depth 64 with deeper text still scanned plain, `--files`/`--spans` in streaming passes. Proven as the first version proves it: a multi-megabyte scan under `ulimit -v`.
- D13, `--history` stays removed; the census method in D9 is its replacement.
- D14, the 21 open P3 and the known gaps from #135 (dashed session slugs, rotting name lists, the round-5 residual notes) are carried as-is. A P3 fix may land only as a listed census false-positive removal with its reason; otherwise the port keeps the quirk.
- D15, fixtures build every made-up secret from fragments at test time; each ported file carries a source-is-clean control proving it matches none of its own rules; the branch passes its own scan (`scrub-check.sh main HEAD`, `tree-check.sh main HEAD`, `wiki-lint.sh`, each exit 0).
