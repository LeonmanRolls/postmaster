# Workhorse spec: 258 Postmaster's own tests pass on macOS, and CI runs them on Linux and macOS for every pull request

## Problem / feature

Postmaster's own tests run only on Linux, so a change can break postmaster on a Mac and nobody sees it. [#217, Postmaster runs on macOS, shown by a macOS job in CI and a fixture run on a Mac](https://github.com/brindlewick/postmaster/issues/217) fixes what breaks the flow itself on a Mac and lands first. Many tests still cannot pass there: they expect process details, program locations, size limits and file-name rules that only Linux has. In the host self-test, the largest one, which checks how launches are placed, stopped and closed, the first Linux-only reading stops the whole test, so about 250 of its 321 checks never run on a Mac.

Some tests skip themselves when a tool is missing, and some pass without checking anything. No list says which, so a skip can hide a failure.

Nothing checks the Bun version. The report behind #217 came from a Mac running Bun 1.3.14, below the minimum of 1.4.2, and nothing told its user. The README does not say which systems postmaster supports, and still lists Python, which postmaster no longer uses.

Done: the tests pass on a Mac, every skip is listed with its reason, every pull request runs the tests on Linux and on a Mac before it merges, every script refuses a Bun that is too old, and the README says what postmaster runs on.

## Acceptance criteria

1. The project's full check passes on a Mac.
2. Every test skipped on either system is named in one skip list, with the reason and the systems it is skipped on.
3. A skipped test that the list does not name for that system fails the check, which names the test.
4. A test that passes without checking anything fails the check, as a hidden skip.
5. Every pull request runs the full check on Linux and on a Mac.
6. The Mac job runs postmaster's scripts with the bash that every Mac comes with.
7. Every pull request also starts postmaster's scripts under a Bun older than the minimum.
8. Under a Bun older than the minimum, a script started through postmaster's one start command stops before it loads, naming the version it needs and the version it found.
9. The postmaster reports a pull request ready to merge, or merges it, only once all its checks have passed on the commit it verified.
10. A failing check sends the pull request back to the run's last leg, on the same branch, naming the failing job.
11. The README names Linux and macOS as supported, and says that Intel Macs are not tested.
12. No list of what postmaster needs names Python.

## Decisions

- **D1 (proposed)** A test is fixed wherever a Mac can do what it tests, and skipped on a Mac only where macOS cannot, such as a file name that is not valid text. Why: a skip leaves its code untested on that system. Instead of: skipping whatever fails on a Mac today.
- **D2 (proposed)** The skip list covers every skip on both systems, including today's skips, such as those for a missing tool or for running as root. Why: one rule for every skip is simpler to keep than two. Instead of: listing only the skips a Mac needs.
- **D3 (proposed)** The check finds a hidden skip by counting what each test checked, so a test that checked nothing fails. Why: Bun's own test report counts each test's checks, so nothing has to guess at the test's code. Instead of: searching the tests' code for early returns, which no search finds completely.
- **D4 (proposed)** No check in the host self-test is skipped: every one runs on a Mac. Why: each of its Linux-only readings has a Mac way that postmaster itself already uses. Instead of: a way to skip its checks one by one, which none of them needs.
- **D5 (proposed)** The Mac job runs on Apple silicon, on the newest macOS GitHub offers, and Intel Macs are not tested. Why: Apple no longer sells Intel Macs, and each Mac job adds to every pull request's wait. Instead of: a second job on an Intel Mac.
- **D6 (given by the user)** Tools a Mac can install are enough, so the Mac runner may have Node, jq, Python or a newer git. Why: there is no Mac with nothing installed. Instead of: a runner with only what a new Mac comes with.
- **D7 (proposed)** Bash is the one exception: the Mac job uses the bash every Mac comes with. Why: postmaster's scripts and the coachman's steps already work with it, and #217 leaves testing them with it to this job. Instead of: a newer bash, a requirement that would buy nothing.
- **D8 (proposed)** In every project, the postmaster waits for a pull request's checks before the merge. Why: the flow keeps no rule for a single repository, and a merge before the Mac job reports could land a Mac failure. Instead of: a GitHub setting that refuses the merge, which the owner must set and which sends nothing back to the run.
- **D9 (proposed)** This ticket enforces the Bun minimum and lands after [#218, Every script runs as its TypeScript file, with no .sh wrapper left](https://github.com/brindlewick/postmaster/issues/218). Why: #218 brings the one command that starts every script, the place for the check. Instead of: enforcing it first, in the wrappers #218 removes.
- **D10 (proposed)** The check runs once, in that start command, before the script loads, so no script carries it. Why: it is written in one place and also catches a Bun too old to load the scripts. Instead of: a line at the top of every script, or postmaster's own Bun settings, where Bun cannot find the check from inside a project.
- **D11 (proposed)** The minimum is written once, in the project's package manifest that already names it, and the check reads it there. Why: one number to change when the minimum moves. Instead of: a second copy of the number in the check.
- **D12 (proposed)** The old-Bun job runs a real older Bun, the version from the report behind #217. Why: only a real one shows the check runs before anything else breaks. Instead of: only a test that pretends to be an older Bun.

## Out of scope

- What #217 fixes, and what only works worse on a Mac: [#259, What only degrades on macOS is fixed, or stated with what the user sees](https://github.com/brindlewick/postmaster/issues/259), whose tests are skipped here where macOS cannot do them today, and which removes the skips it no longer needs.
- The check that refuses new Linux-only code: [#260, A check refuses new Linux-only constructs in the scripts and runbooks](https://github.com/brindlewick/postmaster/issues/260).
- Intel Macs, and macOS versions older than the newest GitHub offers.
- A test that checks something before it skips the rest: the reviewers look for those.
- Making the old shell scripts some tests compare against work on a Mac.
- A script started by hand without the start command: it skips the version check.

## Direction

Linux and macOS. The lanes have no Mac: where a Mac's behaviour can be forced on Linux, as #217's shared process check allows, the tests force it, and the Mac job covers the rest once the pull request is open. It changes the postmaster's landing steps, which are part of the coachman's contract, so it lands only after a fixture run from its branch scores clean. The postmaster that lands this ticket still runs the old landing steps, so it reads this pull request's checks itself and merges only once all have passed. It lands after #217 and after #218. The archived trial scripts and old ticket oracles are not edited.
