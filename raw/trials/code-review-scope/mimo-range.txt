### Bug — `src/page.js:8`: off-by-one, pages return `size + 1` records

```js
return all().slice(start, start + size + 1);
```

`Array.prototype.slice(start, end)` is end-exclusive, so the correct end is `start + size`. The extra `+ 1` makes every full page one record too long, and consecutive pages overlap by one record — so a caller paging through the store sees one record twice, and `pageCount(size)` no longer matches the pages `page(n, size)` actually returns.

Reproduced with 10 records, `size = 5`:

| call | expected | actual |
|---|---|---|
| `page(1, 5)` | `a b c d e` (5) | `a b c d e f` (6) |
| `page(2, 5)` | `f g h i j` (5) | `f g h i j` (5) |

`f` is returned by both pages. The function's own comment ("with `size` records to a page") and `pageCount`'s contract both assume `size` per page.

**Trigger:** any call where at least `size + 1` records remain at `start` — i.e. any non-final page of a full page. Severity is high for callers that page through records or pair `page` with `pageCount`.

**Fix:**
```js
return all().slice(start, start + size);
```
