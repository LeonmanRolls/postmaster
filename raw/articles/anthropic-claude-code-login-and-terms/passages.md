### ANT1 H1-claude-1 Login methods and order of precedence
- finding: Claude Code accepts, in this order: cloud-provider credentials (Bedrock, Vertex, Foundry via env vars), `ANTHROPIC_AUTH_TOKEN` (Bearer header, for gateways), `ANTHROPIC_API_KEY` (X-Api-Key header), `apiKeyHelper` script output, `CLAUDE_CODE_OAUTH_TOKEN` (long-lived subscription token), Anthropic profile / federation credentials, then subscription OAuth credentials from `/login`.
- quote: "`CLAUDE_CODE_OAUTH_TOKEN` environment variable. A long-lived OAuth token generated by `claude setup-token`. Use this for CI pipelines and scripts where browser login isn't available."   (verbatim: two fetches)
- quote: "In non-interactive mode (`-p`), the key is always used when present."   (verbatim: two fetches; about ANTHROPIC_API_KEY)
- source: https://code.claude.com/docs/en/authentication, section "Authentication precedence" ; no last-updated date on page ; read 2026-10-08
- strength: stated

### ANT2 H1-claude-2 Interactive login needs a browser; remote/container case is handled by pasting a code
- finding: First launch opens a browser; if the browser cannot reach the local callback server (WSL2, SSH, containers) it shows a code to paste into the terminal. `/login` and the TUI are interactive; `/login` is "not available" in `-p` mode.
- quote: "This happens when the browser can't reach Claude Code's local callback server, which is common in WSL2, SSH sessions, and containers."   (verbatim: two fetches)
- quote: "Built-in commands that only run in the terminal interface, such as `/login`, aren't available."   (verbatim: from https://code.claude.com/docs/en/headless, one fetch)
- source: https://code.claude.com/docs/en/authentication, "Log in to Claude Code" ; https://code.claude.com/docs/en/headless ; read 2026-10-08
- strength: stated

### ANT3 H1-claude-3 Long-lived token command for CI: `claude setup-token`
- finding: `claude setup-token` runs the browser authorization flow once, prints a one-year OAuth token to the terminal, saves it nowhere; the user sets it as `CLAUDE_CODE_OAUTH_TOKEN` on the other machine. The token is tied to the subscription (Pro, Max, Team, Enterprise); it can only make model requests (no Remote Control, no claude.ai connectors). Bare mode does not read it.
- quote: "For CI pipelines, scripts, or other environments where interactive browser login isn't available, generate a one-year OAuth token with `claude setup-token`"   (verbatim: two fetches)
- quote: "This token authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan."   (verbatim: two fetches)
- quote: "[Bare mode] does not read `CLAUDE_CODE_OAUTH_TOKEN`. If your script passes `--bare`, authenticate with `ANTHROPIC_API_KEY` or an `apiKeyHelper` instead."   (verbatim: two fetches; bracket is mine for "Bare mode")
- source: https://code.claude.com/docs/en/authentication, "Generate a long-lived token" ; read 2026-10-08
- strength: stated

### ANT4 H1-claude-4 Credential file: path, mode, and field NAMES (names only; no values read)

Windows: `%USERPROFILE%\.claude\.credentials.json`. `CLAUDE_CONFIG_DIR` relocates it. The doc does not list the file's field names; no credential file was opened. Field names: not documented on the pages read.
- quote: "On Linux, credentials are stored in `~/.claude/.credentials.json` with file mode `0600`."   (verbatim: two fetches)
- quote: "Claude Code manages `.credentials.json` through `/login` and `/logout`."   (verbatim: two fetches)
- source: https://code.claude.com/docs/en/authentication, "Credential management" ; read 2026-10-08
- strength: stated (path, mode); field names: not found (the authentication page read twice; no grep of the Claude Code binary, which is closed source)

### ANT6 H1-claude-6 Headless `-p` and `--bare`: bare mode ignores the subscription login
- finding: `claude -p` is the non-interactive mode. `--bare` (docs call it recommended for scripted and SDK calls, "will become the default for `-p` in a future release") never reads OAuth credentials or the keychain, so a subscription login does not work with it; use `ANTHROPIC_API_KEY` or `apiKeyHelper`. Without `--bare`, `-p` uses the normal credential chain, including the subscription login.
- quote: "In bare mode, Claude Code never reads OAuth credentials or the system keychain."   (verbatim: one fetch of https://code.claude.com/docs/en/headless, repeated in the authentication page's text "Claude Code doesn't read profiles or federation variables in bare mode"; second read of the headless page still due)
- quote: "`--bare` is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release."   (one fetch)
- source: https://code.claude.com/docs/en/headless, "Start faster with bare mode" ; read 2026-10-08
- strength: stated

### ANT8 H2-claude-1 The subscription login is a short-lived access token plus a refresh token; refresh is automatic

- quote: "Claude Code tried to renew your saved claude.ai login and the OAuth service rejected the stored refresh token, so Claude Code cleared the saved credentials."   (verbatim: two fetches of https://code.claude.com/docs/en/errors, section "Login expired")

### ANT14 H3-claude-1 Base URL and credential variables; wire format is Anthropic Messages
- finding: `ANTHROPIC_BASE_URL` points Claude Code at a gateway that serves the Anthropic Messages format (`/v1/messages`, optional `/v1/messages/count_tokens`, optional `/v1/models`). The credential goes in `ANTHROPIC_AUTH_TOKEN` (sent as `Authorization: Bearer`), `ANTHROPIC_API_KEY` (`x-api-key`) or an `apiKeyHelper` (both headers). Bedrock InvokeModel and Vertex rawPredict formats are also supported through `ANTHROPIC_BEDROCK_BASE_URL` / `ANTHROPIC_VERTEX_BASE_URL` with `CLAUDE_CODE_USE_BEDROCK=1` / `CLAUDE_CODE_USE_VERTEX=1`. Extra headers: `ANTHROPIC_CUSTOM_HEADERS`.
- quote: "Each variable sends the credential in a different HTTP header: `ANTHROPIC_AUTH_TOKEN` in `Authorization: Bearer`, `ANTHROPIC_API_KEY` in `x-api-key`, and `apiKeyHelper` in both."   (verbatim, one fetch https://code.claude.com/docs/en/llm-gateway-connect; the authentication page says the same for the first two, read twice)
- quote: "Any gateway that exposes a supported API format works."   (one fetch https://code.claude.com/docs/en/llm-gateway)
- source: https://code.claude.com/docs/en/llm-gateway-connect ; https://code.claude.com/docs/en/llm-gateway ; https://code.claude.com/docs/en/llm-gateway-protocol ("API formats" table) ; no last-updated dates ; read 2026-10-08
- strength: stated

### ANT16 H3-claude-3 A gateway CAN carry a subscription login (OAuth capability header); with a gateway credential variable set, the subscription is not used
- finding: If only `ANTHROPIC_BASE_URL` is set, the saved claude.ai login stays the active credential, requests carry an OAuth capability in `anthropic-beta`, and the subscription's usage limits and billing apply; the gateway must forward that header or the upstream answers 401. If `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` or `apiKeyHelper` is set, the gateway credential replaces the login and the subscription limits do not apply (billed per token to the credential owner).
- quote: "Setting only that variable, without a gateway credential, doesn't replace the subscription. Requests still route through the gateway, but a saved claude.ai login remains the active credential, so its usage limits and billing apply."   (verbatim, one fetch of https://code.claude.com/docs/en/llm-gateway, section "Subscriptions and gateways")
- quote: "stripping it fails those requests with `401`"   (verbatim, one fetch of https://code.claude.com/docs/en/llm-gateway-protocol, row `anthropic-beta`)
- source: as above ; read 2026-10-08
- strength: stated (single read; second read due)
