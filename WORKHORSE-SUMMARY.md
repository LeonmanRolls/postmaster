## Decisions

1. Split added text at whitespace and count every exact sliding run of six words. Match case
   and punctuation exactly, count repeated occurrences, and do not bridge files.
2. Keep six words, as the audit did. A changed word breaks only nearby runs; the remaining
   unchanged runs still receive lane credit.
3. Treat lane diffs as the source of lane text. Keep the coachman's `took=` reasons for ideas
   rewritten in new words.
4. Report lanes by name and support any number of lanes. For each run, use lane-only, shared
   (two or more lanes), or neither groups.
5. Classify `.md`, `.mdx`, `.rst`, `.adoc` and `.txt` as docs; classify other eligible files,
   including tests, as code.
6. Exclude oracle-added paths, exact root `WORKHORSE-*` record filenames, common lockfiles,
   and paths marked generated by the repository's `.gitattributes`. Detect renames and count
   only changed lines; refuse synthesis ranges containing merge commits.
7. Store one structured `shares.json` beside the run records. Use exact integer counts and
   numerator/denominator shares; display `n/a` when a kind has no runs. Use `SHARES:` for the
   checkpoint line and pass explicit commit hashes to the script.
8. Run Bun with `--no-env-file --config=/dev/null`, and git diffs with `--no-ext-diff`
   and `--no-textconv`, so target repository startup files and diff drivers do not run.
9. Implement the placement rule against the ESLint rule API as an Oxlint plugin. A test must
   have a regular sibling target and cannot live below `test`, `tests` or `__tests__`; a
   target without a test is outside the rule's scope.
10. Pin Oxlint at 1.86.0, keep its default rules enabled, exclude `fixtures/`, and run it with
    `bun x --bun oxlint`. Do not add lint to the project gate in this ticket.
11. Use the fixture-run scoring requirement at ship time because the change edits
    `coachman.md`; it is not an implementation check for this workhorse.
